# omb: the oh-my-batch CLI, end to end

`omb` is a small toolkit for generating and running batch tasks. It has **four**
sub-command groups, three of which form a pipeline:

```
omb combo   →  expand a parameter sweep into rendered files / job dirs
omb batch   →  pack those dirs into N scheduler scripts
omb job     →  submit, retry, and (optionally) block until done
omb shell   →  small guards for driver scripts (try_file, require_env)
```

## The one thing to know first: fire chaining

The CLI is generated by [python-fire](https://github.com/google/python-fire). Methods
on a group **chain**, separated by a bare `-`, and each method returns the object so the
next call continues on it:

```bash
omb combo  add_var TEMP 300 400 -  add_files DATA 'data/*.data' --abs -  make_files ... -  done
#          └─ method ──┘         │  └─ method ──┘                    │  └ method ┘      │ └ ends chain
#                          chain sep                           chain sep
```

- A `combo` chain **ends with `done`** (or `show_combos`, which prints and does not
  return the chain — nothing may follow it).
- `batch` chains **end with `make`**; `job`/`shell` are single calls, not chains.
- Every value after a method name is a positional arg until the next `-`; `--flag`
  sets keyword args. Read any command's help with a trailing `--help`, e.g.
  `omb combo make_files --help`.

## Command map (all groups)

| Group | Command | One-liner |
| --- | --- | --- |
| `combo` | `add_var` / `add_seq` / `add_randint` / `add_rand` | add an axis of literal / sequence / random-int / random-float values |
| | `add_files` / `add_file_set` | add an axis from a glob (one value per file / all joined into one value) |
| | `broadcast` / `set_broadcast` | make an axis ride one-per-combo instead of multiplying (`set_broadcast` alias fixed in 0.7.6; broken in 0.7.5 — use `broadcast` there) |
| | `compute` | derive a new key from existing ones via a Python expression |
| | `shuffle` / `sort` | reorder an axis' values |
| | `make_files` | render a template per combo to a `{i}`/`{KEY}` destination |
| | `dump_combos` / `print` / `run_cmd` | write each combo to JSON / print lines / run a shell command per combo |
| | `show_combos` / `done` | print the expanded table / end the chain (`done --debug` prints too) |
| `batch` | `add_work_dirs` / `filter` | collect work dirs from globs / keep a subset via a Python expr |
| | `add_headers` / `add_header_files` | prepend inline / file content (the `#SBATCH` block) |
| | `add_cmds` / `add_cmd_files` | body commands run inside each work dir |
| | `add_bottoms` / `add_bottom_files` | append inline / file content after the loop |
| | `make` | emit the script(s); `--concurrency N` = N scripts |
| `job` | `slurm submit` / `lsf submit` / `openpbs submit` | submit script globs, with `--wait`, `--max_tries`, `--recovery`, … |
| | `slurm wait` / `lsf wait` / `openpbs wait` | poll existing job ids until terminal |
| `shell` | `try_file` | print the first path that exists (file/dir/glob), else exit 1 |
| | `require_env` | verify env vars are set and non-empty, else exit 1 |

## Which command do I want?

- **Generate many similar input files/dirs from parameters** → `combo` (see
  [reference/combo.md](reference/combo.md)).
- **Turn a pile of ready work dirs into scheduler scripts** → `batch`
  ([reference/batch.md](reference/batch.md)).
- **Submit and babysit those scripts (retry, resume, wait)** → `job`
  ([reference/job.md](reference/job.md)).
- **Fail a driver early if a required input/env is missing** → `shell`
  ([reference/shell.md](reference/shell.md)).

For operational gotchas that bite in real SLURM runs (headers that break `module load`,
output files clobbering each other under `--concurrency`, the guarded-generation
pattern), see [reference/workflow-notes.md](reference/workflow-notes.md).
